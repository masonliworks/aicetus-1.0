# DSH Remote — 产品方案与系统架构 v2（广域网 + 商业化）

> 状态：方案基线（2026-08 与用户对齐后固化）
> 目标：在现有 LAN 版（iOS + Mac 伴侣 + 桥接）基础上，落地广域网中继、账号体系、付费订阅与线路商店。

---

## 1. 产品愿景

用户从 iPhone 随时随地查看和控制自己 Mac 上的 DeepSeek Harness：

- **App Store 免费下载 iOS App**，安装后引导用户到网站下载 Mac 伴侣端；
- **免费可用**：局域网直连 + 1 条限速免费线路；
- **付费升级**：iOS 内 IAP 订阅解锁无限会话与广域网访问；网站购买「线路」（节点 + 带宽配额）提升体验。

---

## 2. 已定决策（Decision Record）

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | iOS 付费方式 | **IAP 订阅 + 网站卖线路** 双轨 | 会话额度属 App 内数字功能，按 Apple 3.1.1 必须走 IAP；线路属服务资源，网站销售 |
| D2 | 广域网方案 | **自建中继服务器**（TCP/TLS） | 实现可控、天然匹配「线路 = 节点 + 带宽配额」的收费模式 |
| D3 | 线路定义 | **节点 + 带宽配额** | 多地区节点，每条线路有带宽/流量上限，按线路数/档位收费 |
| D4 | 账号体系 | **统一账号，Sign in with Apple 为主** | 额度跨设备、可退款、可风控；iOS/网站/Mac 复用同一账号 |

## 4. 连接模型

### 4.1 局域网模式（免费，现有能力）

```
iPhone ──HTTP/SSE──► Mac bridge (3878) ──► DSH (localhost:3080)
```
保持不变，免费用户默认路径。

### 4.2 广域网模式（中继）

```
iPhone ──TLS──► 中继节点 A ──TLS──► Mac bridge (relay 模式) ──► DSH
```

- **Mac 侧拨号**：bridge 以客户端身份连接中继节点（不要求 Mac 有公网 IP/端口映射），成功后上报在线状态。
- **iPhone 侧接入**：登录后从 API 拉取「已配对的 Mac 列表 + 可用节点」，选择连接。
- **双向通道**：iPhone 的控制请求与 DSH 事件流都经中继转发；中继只做寻址与转发，**不落盘业务内容**。
- **端到端加密**：iPhone ↔ bridge 之间在 TLS 之上再做应用层加密（预共享密钥由配对流程协商），中继不可见明文。现有 LAN 配对的 token 机制升级复用。

## 5. 线路模型（节点 + 带宽配额）

### 5.1 节点

- 一台服务器 = 一个节点，可按地区部署（建议起步：香港 / 新加坡 / 日本 / 美西）。
- 节点注册到后端，由后端统一下发节点列表给客户端；节点仅与后端通信（心跳、配额同步），不直接暴露管理端口。

### 5.2 线路 = 节点 + 档位

| 线路档位 | 带宽 | 流量 | 并发连接 | 节点 |
|---|---|---|---|---|
| 免费线路（随账号赠送 1 条） | 2 Mbps | 不限（限速） | 1 | 默认单节点 |
| 标准线路（月付） | 10 Mbps | 100 GB/月 | 2 | 自选 1 节点 |
| 专业线路（月付） | 50 Mbps | 500 GB/月 | 5 | 全节点 |
| 按量线路（流量包） | 不限速 | 按 GB 购买 | 1 | 自选节点 |

- 限速/配额在**中继节点侧强制**（token bucket + 流量计），客户端无法绕过。
- 免费额度强制点同样在节点侧：免费用户同一时刻只允许 1 条中继连接、会话数按权益上限拒绝。

### 5.3 会话额度（免费 vs 付费）

| 能力 | 免费 | IAP 会员 |
|---|---|---|
| 会话数量（同时管理） | 1–2 个 | 不限 |
| 局域网直连 | ✓ | ✓ |
| 广域网（中继） | 1 条免费线路（2 Mbps） | ✓ 全线路 |
| 通知 | ✓ | ✓ |
| 历史消息条数 | 保留最近 50 条 | 全量 |

> 会话额度强制：LAN 模式由 bridge 本地校验（防君子）；广域网模式由中继节点按账号权益校验（硬强制）。

## 6. 账号与计费体系

### 6.1 账号

- **Sign in with Apple**（iOS 与网站均可）：identity token → 后端验证（Apple 公钥 JWS）→ 建立用户。
- 用户表：`users(id, apple_sub, email, status, created_at)`。
- Mac 端登录：展示登录二维码（网站授权）或输入账号令牌；不要求 Mac 装浏览器。

### 6.2 IAP 订阅（iOS 内）

- StoreKit 2，订阅组「DSH Remote 会员」（月/年）。
- **服务端验证**：App 将 transaction JWS 上报后端 → 后端用 App Store Server API 验证并刷新权益（不要只信客户端）。
- 权益变更实时生效：后端 → 中继节点同步 `account_quota`。

### 6.3 线路商店（网站）

- 下单流程：选节点/档位/时长 → 支付（国内：支付宝/微信；海外：Stripe）→ 支付回调 → 开通线路（写 `line_orders` + 生效时间）→ 用户中心可见。
- 线路与账号绑定；到期自动停用（节点侧同步）。

### 6.4 合规要点

- 会话额度属 App 内数字功能 → **必须走 IAP**，网站不得销售 iOS 内权益。
- 线路属中继服务资源 → 网站销售，不触 3.1.1。
- App Store 审核备注：说明需 Mac 伴侣端配合、付费权益内容，附演示视频/录屏。
- 服务条款需声明中继仅用于控制自有设备（避免被用于穿透/违规用途）；境内服务器需备案，建议节点部署在境外。

## 7. 关键流程

1. **配对（广域网）**：Mac 端登录账号并拨号上线 → iPhone 登录同一账号 → 看到该 Mac → 点击连接，双方经中继协商端到端密钥。
2. **订阅**：iOS 内购买 → transaction 上报 → 后端验证 → 权益写库 → 节点同步配额。
3. **购买线路**：网站下单 → 支付 → 回调开通 → 用户中心/客户端展示剩余流量与到期时间。

## 8. 技术选型建议

| 层 | 选型 | 理由 |
|---|---|---|
| 中继 daemon | Go（或 Node 起步） | 单二进制部署、高并发；MVP 可先用 Node 复用 bridge 协议，稳定后迁 Go |
| 后端 API | Node + Fastify/Express + PostgreSQL | 与 bridge 同栈；Postgres 支撑订单/用量统计 |
| 网站 | Next.js（SSR） | 落地页 + 商店 + 用户中心一体；支付 SDK 生态全 |
| iOS | SwiftUI + StoreKit 2 + AuthenticationServices | 现状栈，直接扩展 |
| Mac | SwiftUI（现状）+ bridge 增加 relay 客户端 | 改动集中在 bridge |
| 部署 | 境外 VPS（香港/新加坡起步）+ Caddy/nginx + TLS | 免备案、国内延迟可控 |
| 支付 | Stripe（海外）+ 支付宝/微信（国内） | 覆盖主流 |

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| IAP 合规审查失败 | 无法上架/下架 | 严格走 StoreKit 2，权益差异全部 IAP；网站只卖线路 |
| 中继带宽成本失控 | 亏损 | 免费线路严格限速；按量/流量包定价覆盖成本；用量监控告警 |
| 中继节点被滥用 | 封禁/合规风险 | 服务条款限定自有设备；登录 + 设备白名单；滥用封禁 |
| 审核无法演示连接 | 被拒 | 审核备注 + 演示视频 + 截图说明配对流程 |
| 端到端安全 | 用户数据泄露 | 中继之上应用层加密；密钥协商不走明文 |
| Apple 抽成（15–30%） | 利润率 | 定价时计入；年订阅、家庭共享定价策略 |
